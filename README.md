маршрутизация курьерской доставки

Сервис для учёта курьерских отправлений и маршрутов. 
Через REST API можно создавать посылки, собирать маршруты с остановками,
назначать посылки на точки маршрута и вести статусы доставки.

Сущности(не в виде гномика)

- Пользователь - /api/users — отправитель (имя, email, роль)
- Отправление - /api/shipments — посылка: адрес, вес, статус, кто отправил
- Маршрут - /api/routes— дата, лимит суммарного веса, статус
- Остановка - /api/stops— точка маршрута, адрес и порядковый номер
- Назначение - /api/shipment-assignments — связь посылки с остановкой

Связи: у пользователя несколько отправлений, у маршрута несколько остановок,
посылка через назначение привязывается к одной остановке.
По каждой сущности есть CRUD: список, получение по id, создание, изменение, удаление.



Не обычный CRUD — зависят от текущих статусов и меняют сразу 
несколько связанных объектов. Если условие не выполнено, операция не проходит.

1. назначить посылку - POST /api/operations/assign-shipment  
   Посылка ставится на остановку, проверяется лимит веса маршрута.
2. Запустить маршрут - POST /api/operations/start-route/{id}  
   Маршрут переходит в работу, посылки — «в пути» (нужны остановки и назначения).
3. Завершить доставку - POST /api/operations/complete-delivery/{id} 
   Назначение закрывается, посылка помечается доставленной.
4. Отменить посылку** - POST /api/operations/cancel-shipment/{id}  
   Доставленную отменить нельзя. Назначение снимается, вес на маршруте освобождается.
5. Переназначить - POST /api/operations/reassign-shipment  
   Посылка переносится на другую остановку с проверкой лимита веса.
6. Закрыть маршрут - POST /api/operations/close-route/{id}  
   Можно, когда все доставки по маршруту уже завершены.

Сценарий: завели данные -> назначили посылки -> запустили маршрут -> отметили доставки -> закрыли маршрут.

Примеры запросов — в файле api.http.
